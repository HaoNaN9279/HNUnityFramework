## 🥇 P0 — 核心阻塞项

> 被最多其他模块依赖。这些不做，后续模块的工作都会受阻或妥协。

### 1. D2/C1 — MemoryPack 序列化

- **状态**：📋 完全未开始（`Core/Capability/Serialization/` 目录不存在）
- **依赖**：MemoryPack 包
- **阻塞**：C6 网络（消息序列化）、C8 存储（存档二进制）、L4 Sheet（二进制配置表）、C2 Debug（日志二进制导出）
- **工作量**：中
- **建议**：**P0 最高优先级**。引入 MemoryPack 包后实现包装器 + 接口，Unity 格式化器按需补充。

### 2. C7 — 事件总线

- **状态**：📋 完全未开始
- **核心接口**：`IEventBus` — `Subscribe<T>` / `Unsubscribe<T>` / `Publish<T>`
- **阻塞**：L1 MVC Model 变更通知、所有模块间解耦通信
- **工作量**：小（2 个文件，纯 C#）
- **建议**：P0 末位。无外部依赖，1 天可完成。建议 MemoryPack 后立即做。

## 🥈 P1 — 高价值独立能力

> 日常游戏开发刚需，不阻塞其他模块但价值极高。

### 3. D3 — Debug 基础设施

- **状态**：✅ 数据模型已实现（LogLevel / ILogChannel / LogEntry / IDebugHub / IDebugCommand / DebugHub）；🚧 运行时部分待补完
- **阻塞**：C2 Debug 系统、E3 Debug Hub Editor、C5 日志扩展
- **待补完**：DebugHub Capability 层注册 + Unity RuntimeDebugConsole（`~` 键调试终端）
- **工作量**：小（数据模型已完成，剩余 2-3 天）
- **建议**：数据模型已完成，不再是 P0 阻塞项。P1 阶段顺手补完。

### 4. C14 — 输入系统

- **状态**：✅ 已完成
- **核心实现**：`IInputManager` + `IInputBlocker`（Core 接口），`InputManager` + `InputBlocker` + `DeviceDetector` + `TouchInputAdapter` + `InputActionAssetLoader`（Unity 实现）
- **依赖**：`com.unity.inputsystem`
- **工作量**：小-中
- **说明**：V1 已完整实现事件驱动的输入动作注册/注销、优先级屏蔽栈、多设备自动检测、触屏虚拟控件。`SetControlScheme` 和 `LoadFromAsset`（Addressables）为占位实现，`InputDebugger` 编辑器工具待后续补充。

### 5. C15 — 热更新与脚本系统

- **状态**：✅ 已完成
- **方案**：HybridCLR（C# 热更新）+ xLua（Mod 脚本）
- **依赖**：HybridCLR 包、xLua 包
- **实现**：Core 层抽象接口（IScriptEngine/IScriptMod/ModState/ScriptModConfig/IHotUpdateEntry），Unity 层 HybridCLRAdapter（AOT 元数据加载、热更 DLL 加载、入口发现与激活）+ LuaModManager（Mod 生命周期管理、LuaEnv 沙箱隔离、API 白名单机制），Editor 层构建管线处理器（AOT 元数据生成、原生库拷贝、安装验证）

### 6. C13/V1 — UI 系统

- **状态**：📋 完全未开始（Core/Unity 目录均不存在）
- **核心接口**：`IUIManager`（7 层 Canvas 栈导航）、`RedDotNode`（红点树父子聚合）
- **依赖**：LitMotion（UI 动画引擎）
- **工作量**：**大**（框架最复杂的高层能力之一）
- **建议**：**P1 最高优先级**，框架核心价值点。分两步：先 Core 接口 + UIManager 基础栈，再做 Panel 类型扩展（UIDialog/UIToast/UIGuide）和 RedDotManager。

### 7. D2 — HNFixedPoint + HNRandom

- **状态**：📋 完全未开始
- **依赖**：无（纯 C# 数学）
- **工作量**：小-中
- **建议**：独立且简单，可随时穿插。对 C6 网络同步的确定性至关重要。

## P3 — 游戏功能子系统

> 大型子系统，价值高但工作量大，可并行推进。

### 13. L3/V2 — Entity 系统 + ViewFactory

- **状态**：🚧 V2 有骨架类（ViewFactory `return null`，EntityView 空基类）；Core L3 📋
- **依赖**：L1 MVC
- **工作量**：中
- **建议**：与 MVC 配合使用。V2 骨架已有，补完实现即可。

### 14. C6 — 网络系统 + 网络同步深度扩展

- **编号**：C6（Core + Unity）
- **当前状态**：🚧 接口 + 骨架（throw NotImplemented）
- **封装策略**：最大程度复用 FishNet 内置能力（NetworkBehaviour/SyncVar/RPC/Spawn/Interest Management），不自建同步协议。预置 MonoBehaviour 组件（NetworkTransform/NetworkAnimator）由框架自行封装。

  | 位置 | 状态 |
  |------|:----:|
  | Core `INetworkManager` | 🚧 接口需扩展（IsServer/IsClient/连接事件） |
  | Unity `FishNet*` 4 个文件 | 🚧 全部 `throw NotImplementedException` |

- **已知问题**：
  - 命名空间 `HN.Framework.Capability.Core.Network` 应修正为 `HN.Framework.Core.Capability.Network`
  - FishNet 包需要先引入
  - 现有 4 个 FishNet 适配器文件（FishNetNetworkManager/FishNetMessageBus/FishNetConnectionAdapter/FishNetSerializerAdapter）需按新方案重构

- **网络同步深度扩展（📋 新规划）：**
  - **C6.1 状态同步** — 基于 FishNet SyncVar/SyncList，IReadOnlyModel 绑定客户端 View
  - **C6.2 预测与校验** — 使用 FishNet Prediction + Lag Compensation API；MemoryPack 序列化预测状态
  - **C6.3 实体权限** — FishNet NetworkObject.Owner + Spawn/Despawn，与 EntityManager(L3) 集成

- **工作量**：大（基础网络封装 + 同步集成）
- **依赖**：C1 MemoryPack（Custom Serializer 注册）、D2 HNFixedPoint（帧同步确定性）
- **建议**：FishNet 内置了大量同步基础设施，工作量较原方案（自建同步协议）大幅降低。

### 15. L7 — 战斗数值体系

- **状态**：📋 规划完成，待实现
- **核心模型**：`AttributeContainer<TCalc>`（属性+修正器）、`DamagePipeline`（伤害管线）、`Buff/DeBuff` 生命周期
- **依赖**：L3 Entity、C7 EventBus
- **工作量**：大
- **建议**：RPG/动作/卡牌/MOBA 战斗刚需。分阶段：属性容器+伤害管线 → Buff 系统 → 技能系统。

### 16. L9 — 物品/背包/装备框架

- **状态**：📋 规划完成，待实现
- **核心模型**：`ItemData` / `InventoryContainer` / `EquipmentSlot` / `IItemDropTable`
- **依赖**：L3 Entity、C4 AssetManager、C1 MemoryPack
- **工作量**：中-大
- **建议**：RPG/生存/卡牌核心系统。数据模型先行，运行时容器后续。

### 17. C11/V5 — 音频系统

- **状态**：📋 完全未开始
- **依赖**：miniaudio（原生 C 库）、SteamAudio
- **工作量**：**极大**（C 原生库桥接 + 3D 音频）
- **建议**：**技术难度最高模块**，需 C# 包装原生 C 库。如项目音频需求简单，可暂用 Unity 内置 Audio。

### 18. C12 — 过场动画系统

- **状态**：📋 完全未开始
- **依赖**：`com.unity.timeline`
- **工作量**：大
- **建议**：核心创新点 — `CutsceneBindingResolver`（自定义 IExposedPropertyTable 自动角色绑定）。有剧情需求则提前。

## 建议推进策略

### 阶段一：打地基（P0）
```
MemoryPack 序列化 (C1) → EventBus (C7)
```
- 预计耗时：1-2 周
- 前提：D3 Debug 数据模型已完成，不再是阻塞项
- 产出：高性能序列化基础、模块间事件通信

### 阶段二：核心能力（P1 + P2）
```
D3 Debug 运行时收尾 (2-3天) ─── 基于已完成的数据模型
Input 系统 (C14)          ─── 游戏基础刚需
热更新 (C15 HybridCLR)    ─── 手游发版刚需 ✅
UI 系统 (C13+V1)          ─── 框架核心价值点
物理系统 (C16)            ─── 物理交互刚需
摄像机 (C17)              ─── 3D 游戏刚需
Debug 系统 (C2)           ─── 基于 D3
本地化 (C3)               ─── 可并行
Sheet 运行时 (L4)         ─── 补完 E7 的最后缺口
HNFixedPoint/HNRandom     ─── 独立穿插
```
- 预计耗时：4-6 周
- 产出：框架在项目中可投入使用的核心功能集 + 全套工具链

### 阶段三：游戏子系统（P3）
```
Entity + ViewFactory (L3+V2)
网络系统 (C6) + 同步深度  ─── 需要阶段一的 MemoryPack
战斗数值体系 (L7)         ─── 依赖 L3 + C7
物品背包 (L9)             ─── 依赖 L3 + C4
音频系统 (C11/V5)          ─── 技术攻坚
过场动画 (C12)             ─── Timeline 集成
```
- 预计耗时：5-8 周（音频和网络并行攻坚）
- 产出：完整的游戏开发框架能力

### 阶段四：动画与进阶工具（P4 + P5）
```
Graph + Graph Editor (L5+E2)
Animation + Playable (L6+V4)
Editor UI 扩展 (E1)
任务成就系统 (L8)
AI 行为框架 (L10)
场景流送 (C19)
性能监控 (C21)
数据安全 (C18)
昼夜天气 (C20)
资源质检 + 自动化构建 (E9)
渲染管线 / Addressables 扩展
```
- 预计耗时：4-6 周（可并行推动）
- 产出：进阶能力（可视动画编辑器、高性能动画系统、AI 框架）+ 运维工程化
