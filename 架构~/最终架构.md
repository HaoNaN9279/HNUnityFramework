# HNUnityFramework 最终架构

> 源自「重构规划.md」的架构设计思路，基于「阿里郎」提出的三层模型（DriverLayer → CapabilityModule → Level），
> 融合七层依赖倒置约束与菱形多仓库解耦原则。
>
> **命名空间已从 `HN.Framework` 更名为 `HN.Framework.Core`**，程序集拆分已完成（Core / Unity / Editor）。
>
> 生成日期：2026-07-02

## 一、框架定位与多仓库架构

### 1.1 四仓库菱形依赖

项目由四个独立仓库组成，形成**单向菱形依赖**——框架在最底层，上层仓库互不直接依赖：

```
                       ┌─────────────────┐
                       │   策划设计内容    │  ← 最上层
                       │   (Design Repo)  │
                       │  零代码，纯装配   │
                       │  Prefab / 场景 / UI组装 │
                       └───────┬─┬───────┘
                               │ │
                    ┌──────────┘ └──────────┐
                    │                       │
                    ▼                       ▼
        ┌──────────────────┐    ┌──────────────────┐
        │   项目脚本         │    │   纯美术资源       │
        │  (Scripts Repo)   │    │   (Art Repo)      │
        │  程序维护          │    │  美术维护          │
        │  游戏玩法逻辑       │    │  零代码，按实体组织 │
        │  视图层代码         │    │  模型/贴图/材质/动画│
        │  Editor工具        │    │  Shader/RenderPipeline│
        └────────┬─────────┘    └────────┬──────────┘
                 │                       │
                 └───────────┬───────────┘
                             │
                             ▼
                ┌────────────────────────┐
                │   HNUnityFramework      │  ← 最底层（本仓库）
                │   (Framework Repo)      │
                │                        │
                │  HN.Framework.Core     │  ← 纯 C# 逻辑层
                │  HN.Framework.Unity    │  ← Unity 平台层
                │  HN.Framework.Editor   │  ← 编辑器工具层
                └────────────────────────┘
```

### 1.2 仓库职责与边界

| 仓库 | 内容 | 维护团队 | 包含代码？ | 依赖 |
|------|------|----------|:----------:|------|
| **Framework** | 框架自身：DriverLayer + CapabilityModule 接口 + Level 基础设施 | 框架开发 | ✅ | Unity + Addressables |
| **Art** | 按实体分类的美术资产（模型/贴图/材质/动画）；项目 Shader 文件 + 渲染管线配置 | 美术 | ❌ | Framework（Shader 依赖） |
| **Scripts** | 游戏玩法逻辑 + 视图层代码 + Editor 工具 | 程序 | ✅ | Framework（asmdef 引用） |
| **Design** | 引用美术资源的 Prefab、游戏逻辑场景、UI 组装 | 策划 | ❌ | Art + Scripts（Unity GUID 引用） |

**三大基石技术选型：**

| 领域 | 技术 | 说明 |
|------|------|------|
| 资源管理 | **Addressables** | 替代 Resources；`ResourcesOperator` 保留但标记 deprecated |
| 配置表 | **Luban** | Excel → C# 代码生成 + 运行时数据加载；框架 Sheet 编辑器负责 Unity 内资源引用编辑 |
| 网络 | **FishNet** | 通过 `HN.Framework.Unity` 封装传输层；`HN.Framework.Core`（纯 C#）不直接引用 FishNet |

### 1.3 解耦原则

```
程序写代码时 ──→ 不需要美术资源，不需要策划 Prefab，只需 Framework
美术做资源时 ──→ 不需要程序代码，不需要策划场景，只需 Framework（Shader 依赖）
策划搭场景时 ──→ 不需要修改代码，不需要修改源美术资产，引用 Art + Scripts 装配
```

**核心规则：**
- **单向依赖**：上层依赖下层，下层绝不依赖上层
- **Design 是装配层**：零代码，只有 `.prefab` / `.unity` / `.asset`
- **Art 是纯资源**：不含 Prefab、不含代码，按实体分目录（不按资产类型分）
- **Scripts 是纯代码**：包含 LogicModule（玩法逻辑）和 ViewModule（视图代码）

### 1.4 架构层 → 仓库映射

| 架构层 | 归属仓库 |
|-----------|----------|
| **Level.ViewModule**（视图代码：ViewFactory 等） | Scripts |
| **Level.ViewModule**（3D 场景、Pawn、UI 的 Prefab 装配） | Design |
| **Level.LogicModule**（任务/战斗/商城等玩法逻辑） | Scripts |
| **CapabilityModule**（接口定义 + 平台实现） | Framework + Scripts（游戏特定实现） |
| **DriverLayer**（GameWorld + 基础类库 + 平台抽象） | Framework |
| **Editor 工具** | Framework + Scripts |

## 二、三层架构模型

### 2.1 架构全景

```
┌─────────────────────────────────────────────────────────────┐
│                       Level (关卡层)                         │
│  ┌─────────────────────┐   ┌─────────────────────────────┐  │
│  │    ViewModule        │<─>│      LogicModule            │  │
│  │  (视图层, 纯表现)     │   │   (数据/逻辑层, 纯逻辑)      │  │
│  │  3D场景  Pawn  UI    │   │  任务 Entity 场景 战斗      │  │
│  │  相机   特效  天气    │   │  成就 商城  剧情  导航      │  │
│  │  过场   音频  输入    │   │  天气  技能  背包  ...      │  │
│  └─────────────────────┘   └─────────────────────────────┘  │
└───────────────────────────┬─┬───────────────────────────────┘
                            │ │  双向通信
┌───────────────────────────┼─┼───────────────────────────────┐
│                  CapabilityModule (通用能力层)                   │
│                            │ │                               │
│  UI系统  日志系统  资源管理  音频系统  网络系统                 │
│  事件系统  关卡重置  空间查询  存储系统  任务调度器             │
└───────────────────────────┬─────────────────────────────────┘
                            │  单向依赖
┌───────────────────────────┼─────────────────────────────────┐
│                  DriverLayer (驱动层)                         │
│                            ▼                                 │
│  GameWorld     基础类库       游戏引擎       平台抽象层       │
│  全局驱动根节点  算法/工具      Unity         Unity 适配      │
└─────────────────────────────────────────────────────────────┘
```

**依赖规则：**
- `Level` ↔ `CapabilityModule`：双向通信
- `CapabilityModule` → `DriverLayer`：单向依赖
- `DriverLayer`：自底向上，GameWorld 在最上层驱动所有模块

### 2.2 框架提供 vs 上层仓库提供

框架（本仓库）提供的是**可跨项目复用的基础设施**：

| 架构层 | 框架提供 | 上层仓库提供 |
|--------|----------|-------------|
| **DriverLayer** | GameWorld、基础类库（HNLogicTime、ReferencePool、ITickable 等）、平台抽象层 | — |
| **CapabilityModule** | 各服务接口定义（IAssetOperator、ILogProvider 等）+ 通用实现（ProcedureManager、ObjectPoolManager） | 游戏特定实现（GameNetworkService、GameStorageService）→ Scripts |
| **Level.LogicModule** | MVC 框架、HFSM、Entity 基类、Sheet 属性 | 具体玩法逻辑（Task/Battle/Shop）→ Scripts |
| **Level.ViewModule** | ViewFactory 基类、EntityView 基类、PropertyBinder | 具体视图代码（UI 逻辑、相机控制、动画控制）→ Scripts；Prefab 装配 → Design |

## 三、程序集规划

### 3.1 程序集清单

| 程序集 | 架构层 | 内容 | 外部依赖 | noEngineRefs | 命名空间 |
|--------|--------|------|----------|:------------:|----------|
| `HN.Framework.Core` | DriverLayer（基础类库 + GameWorld）+ CapabilityModule（纯 C# 部分）+ Level.Logic（基础设施） | 纯 C# 代码 | **无**（仅 .NET Standard 2.1） | ✅ true | `HN.Framework.Core.*` |
| `HN.Framework.Unity` | DriverLayer（平台抽象层）+ CapabilityModule（Addressables/网络封装）+ Level.View（基础设施） | Unity 依赖代码 | UnityEngine + Addressables + FishNet | ❌ false | `HN.Framework.Unity.*` |
| `HN.Framework.Editor` | 编辑器工具层 | 编辑器扩展 + Sheet 编辑器 + Addressables 分组管理 | UnityEditor | ❌ false | `HN.Framework.Editor` |

### 3.2 依赖关系图

```
┌─────────────────────────┐
│   HN.Framework.Editor   │  Editor only
│   (Editor only)         │
└───────────┬─────────────┘
            │ 引用
    ┌───────┴───────────────────────┐
    ▼                               ▼
┌──────────────────┐  ┌──────────────────────────────┐
│ HN.Framework     │  │     HN.Framework.Unity       │
│  .Core           │  │                              │
│  (noEngineRefs   │  │  + UnityEngine               │
│   = true)        │  │  + Addressables              │
│                  │  │  + FishNet (封装)             │
│  GameWorld       │◄─┤  (引用 HN.Framework.Core)     │
│  Capability 接口  │  │                              │
│  Level.Logic     │  └──────────────────────────────┘
│  基础设施         │
└──────────────────┘
```

### 3.3 跨仓库程序集依赖规则

| 依赖方向 | 方式 | 说明 |
|----------|------|------|
| Scripts → Framework | asmdef `references` | 显式引用 Core 和 Unity 的 GUID |
| Art → Framework | Unity 资源引用 | Shader 引用 Framework 的 ShaderLibrary |
| Design → Scripts | Prefab 组件引用 | Prefab 上挂载的 MonoBehaviour 来自 Scripts 仓库 |
| Design → Art | Prefab 资源引用 | 引用的 Mesh/Material 来自 Art 仓库 |
| Framework → 上层 | **禁止** | asmdef 的 references 绝不包含上层 GUID |
| `Core` → FishNet | **禁止** | 纯 C# 层只定义 `INetworkManager` 接口 |
| `Unity` → FishNet | asmdef `references` | 唯一在 Framework 内引用 FishNet 的位置 |

## 六、GameWorld 驱动模型

### 6.1 静态单例消除

所有有状态的 Manager 从静态单例改为 GameWorld 持有的实例，彻底消除全局状态：

| 类 | 旧模式 | 新模式 |
|----|--------|--------|
| `ControllerManager` | `static ControllerManager Instance` | `world.ControllerManager`（实例） |
| `ObjectPoolManager` | `static ObjectPoolManager Instance` | `world.PoolManager`（实例） |
| `ProcedureManager` | `static ProcedureManager Instance` | `world.ProcedureManager`（实例） |
| `ReferencePool` | `static` 全部静态 | **保持不变** — 线程安全工具类 |
| `HNLogicTime` | `static` 全部静态 | **保持不变** — 纯数据类 |

### 6.2 GameWorld 双组件模式

```
                    HN.Framework.Core（纯 C#）            HN.Framework.Unity（Unity 层）
                    ────────────────────────            ──────────────────────────────

                    ┌──────────────────────┐           ┌──────────────────────────┐
                    │     GameWorld        │◄──────────│    GameWorldDriver        │
                    │                      │  持有并驱动 │   (MonoBehaviour)         │
                    │  · PoolManager       │           │                          │
                    │  · ProcedureManager  │           │  Awake() → new GameWorld │
                    │  · ControllerManager │           │          → 注入平台实现   │
                    │                      │           │          → World.Initialize│
                    │  · LogProvider       │←─────────│  Update() → World.Tick() │
                    │  · AssetOperator     │  注入      │  LateUpdate() → LateTick │
                    │  · NetworkManager    │           │                          │
                    └──────────────────────┘           └──────────────────────────┘
                                                        ▲
                                                        │ 继承
                                              ┌─────────┴───────────┐
                                              │     GameEntry        │ ← Scripts 仓库
                                              │  (Scripts Repo)      │
                                              │                      │
                                              │  OnRegisterGameModules│
                                              │    → 注册游戏特定模块 │
                                              └──────────────────────┘
```

**GameWorld**（纯 C#）负责：
- 创建并持有所有框架内置模块
- 驱动 Tick 循环（Tick → LateTick）
- 暴露平台适配接口和游戏服务接口，由外部注入

**GameWorldDriver**（MonoBehaviour）负责：
- 在 Awake 中创建 GameWorld
- 注入平台适配层实现（UnityLogProvider、AddressablesOperator 等）
- 调用 `OnRegisterGameModules`（虚方法，由 Scripts 仓库的 GameEntry 重写）
- 在 Unity 生命周期中驱动 GameWorld 的 Tick

**Scripts 仓库的 GameEntry**：
```csharp
// 继承 Framework 的 GameWorldDriver，重写 OnRegisterGameModules
public class GameEntry : GameWorldDriver
{
    protected override void OnRegisterGameModules(GameWorld world)
    {
        // 注册游戏特定的 Controller
        world.ControllerManager.RegisterController(new BattleController(world));
        // 注入游戏特定的服务实现
        world.NetworkManager = new GameNetworkService();
        world.StorageProvider = new GameStorageService();
    }
}
```

## 七、关键设计决策

### 7.1 ReferencePool 和 HNLogicTime 为何保留静态？

| 类 | 保留静态的理由 |
|----|---------------|
| `ReferencePool` | 线程安全的零 GC 工具类，不持有任何业务状态。类比 .NET 的 `ArrayPool<T>.Shared`。所有操作无副作用，无需生命周期管理。 |
| `HNLogicTime` | 纯数据类，仅提供 Time/DeltaTime/LogicFrameCount 三个静态属性。不依赖任何外部服务，也不被任何模块管理。 |

### 7.2 ObjectPool 拆分边界

`ObjectPool` 系统按 Unity 依赖边界拆分为两部分：

```
HN.Framework.Core                        HN.Framework.Unity
───────────────────                     ─────────────────────
PoolBase (抽象)                         GameObjectPoolBase
ObjectPool<T> (泛型 C# 池)              GameObjectPool
PooledObjectBase                         PooledObject<T> (包装 UnityEngine.Object)
ObjectPoolManager                       (通过 PoolBase 接口管理所有池)
```

`ObjectPoolManager` 通过 `PoolBase` 抽象接口管理所有池，Unity 侧的 `GameObjectPool` 实例由 `GameWorldDriver` 创建并注册，因此 `ObjectPoolManager` 可留在纯 C# 程序集中。

### 7.3 FishNet 封装策略

**核心原则**：FishNet 只出现在 `HN.Framework.Unity`，`HN.Framework.Core`（纯 C#）只定义接口和消息协议。

```
HN.Framework.Core (纯 C#)                HN.Framework.Unity
────────────────────────                ─────────────────────
INetworkManager (接口)          ←实现── FishNetNetworkManager
  · Connect()                            · 封装 FishNet Client/Server API
  · Send<T>(T message)                   · 管理 NetworkConnection
  · RegisterHandler<T>()                 · 注入自定义序列化器

MessageBase (基类)                       FishNetMessageBus
网络消息类 (纯 C# struct/class)            · 消息路由适配
                                         FishNetConnectionAdapter
                                          · 连接状态适配
                                         FishNetSerializerAdapter
                                          · MemoryPack 注入 FishNet
```

| FishNet 能力 | 策略 |
|-------------|------|
| 底层传输（TCP/UDP） | ✅ 直接使用 |
| 连接管理（Connect/Disconnect/心跳） | ✅ 直接使用 |
| NetworkBehaviour / SyncVar / RPC | ❌ **不用**，改用自定义消息协议 |
| 网络对象生成（Spawn） | ❌ **不用**，逻辑层 EntityManager 管理，网络层只同步 ID + 状态 |
| 带宽统计 / 调试工具 | ✅ 通过接口暴露 |

### 7.4 Luban + Sheet 协作模式

| 工具 | 负责 | 产出 |
|------|------|------|
| **Luban**（外部工具） | Excel/CSV → C# 代码生成 + 二进制数据导出 | 生成的 `Tables` 类 + .bin 数据文件 |
| **Sheet 编辑器**（框架） | Unity Editor 中编辑 Luban 数据表的**资源引用字段** | ScriptableObject，存储数据行 → Addressables 资源地址映射 |

工作流：策划修改 Excel → Luban 生成 C# 代码 + .bin → Unity Sheet 编辑器加载数据 → 策划为资源字段选择 Addressables 资源 → 运行时 Luban 加载数据 + Sheet 查询资源地址 → `Addressables.LoadAssetAsync()`

### 7.5 Addressables 资源策略

| 操作器 | 状态 | 说明 |
|--------|------|------|
| `AddressablesOperator` | ✅ 主要使用 | 运行时资源加载的唯一路径 |
| `AssetDatabaseOperator` | ✅ 保留（Editor only） | 编辑器下快速迭代，通过 `IAssetOperator` 统一调用 |
| `ResourcesOperator` | ⚠️ deprecated | 保留代码但标记 `[Obsolete]` |

### 7.6 UNITY_SERVER 宏策略

| 适用范围 | 做法 |
|----------|------|
| `HN.Framework.Core` 程序集 | **禁止使用** — 保证客户端/服务端代码完全一致 |
| `HN.Framework.Unity` 渲染相关代码 | `#if !UNITY_SERVER` 包裹（Headless 服务端无需渲染） |
| `HN.Framework.Editor` | Editor only，天然不进入构建 |

### 7.7 自定义渲染管线 (SRP) 分工

| 内容 | 仓库 | 说明 |
|------|------|------|
| SRP 核心代码 + ShaderLibrary | Framework → `HN.Framework.Unity` | 框架提供渲染管线实现和基础 Shader 库 |
| 项目实际使用的 Shader | Art Repo → `Shaders/` | 基于 Framework ShaderLibrary 编写 |
| SRP Asset 配置实例 | Art Repo → `RenderPipeline/` | 渲染质量、管线参数配置（无代码） |

### 7.8 Art 仓库目录组织原则

**按实体分类，不按资产类型分类**：

```
❌ 传统方式（按类型分）            ✅ 新方式（按实体分）
Art/                              Art/
├── Models/                       ├── Characters/
├── Textures/                     │   ├── Hero_Warrior/
├── Materials/                    │   │   ├── model.fbx
└── Animations/                   │   │   ├── diffuse.png
                                  │   │   ├── material.mat
                                  │   │   └── idle.anim
                                  │   └── Hero_Mage/
                                  └── Environment/
```

### C. 核心约束总结

1. **三层架构为唯一骨架**：DriverLayer → CapabilityModule → Level（ViewModule ↔ LogicModule）
2. **每个文件可精确定位**到 D1-D4 / S1-S11 / L1-L9 / V1-V7
3. **消除静态单例**：GameWorld 作为唯一持有者，通过实例组合而非全局访问
4. **菱形依赖解耦**：Framework → Scripts / Art → Design，四仓库单向依赖
5. **Framework 不引用上层**：asmdef 的 `references` 不包含任何上层仓库的程序集 GUID
6. **代码所属明确**：框架代码（可跨项目复用）在 Framework 仓库；游戏特定代码在 Scripts 仓库
7. **程序集强制约束**：`HN.Framework.Core` 设置 `noEngineReferences: true`，编译期强制零 Unity 引用
8. **FishNet 隔离**：仅 `HN.Framework.Unity` 引用 FishNet，纯 C# 层只定义接口和消息协议
9. **UNITY_SERVER 仅用于编译裁剪**：不做运行时逻辑分支
