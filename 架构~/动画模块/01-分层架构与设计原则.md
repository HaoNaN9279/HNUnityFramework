## 一、设计目标

1. 五层架构按职责切 **两侧**：逻辑侧纯 C#（Core，`noEngineReferences: true`，永不停）；表现侧 Unity（受可见性 / LOD 控制）
2. 角色不在视野 → 逻辑侧照常 Tick，表现侧停止
3. 表现侧 LOD 分级降本
4. 不破坏现有编号：**L6** = Core（数据模型 + 逻辑运行时）；**V4** = Unity（表现运行时）
5. 表现层支持 **Unity Jobs + Burst** 加速（姿态计算 / 批处理），逻辑层（Core）保持主线程纯 C#、**不 Job 化**
6. 表现层支持形变扩展 **PSD（Pose Space Deformation）+ DQ Skinning**，三种应用路径（BlendShape / Compute Deformation / DOTS Deformation）**全支持**
7. 表现层支持 **2D 骨骼动画子系统（Spine 类 cutout）**：仅导入 + 渲染，兼容 Spine JSON，双渲染方案（CPU Mesh / GPU Compute）用户可选

## 二、核心切分原则

| 问题 | 归属 | 理由 |
|------|:----:|------|
| 播哪个 clip / 状态机转换 | 逻辑 | 纯决策，无 Unity |
| 混合权重计算 | 逻辑 | 纯数学，给定参数算权重 |
| 根运动积分 / 位移意图 | 逻辑 | 确定性；位移交移动系统，动画只出姿态 |
| 帧事件（攻击判定） | 逻辑 | 不可见时也不能丢 |
| 权重的**应用**（Mixer 混合） | 表现 | 需 Playable |
| IK 求解 | 表现 | 读 `AnimationStream` |
| 骨骼姿态输出 / Skinning | 表现 | 纯渲染 |
| PSD 校正形变 / DQ Skinning | 表现 | 依赖最终骨骼姿态，与逻辑无关 |
| 2D 骨骼求值 / 蒙皮 / mesh 构建 | 表现 | 纯渲染，与逻辑无关 |
| 可见性 / LOD 控制 | 表现 | 纯性能策略 |

> 一句话：**逻辑层决定「播什么 / 什么状态 / 什么权重」，表现层负责「把快照还原成骨骼姿态」。**

**收益**：逻辑层纯 C# + 确定性（**Fixed64，已定**）→ 支持帧同步 / 回放；表现层任意降级不影响逻辑正确性。

## 三、分层架构

### 3.1 逻辑侧 / 表现侧

```
┌──────────── 逻辑层 (Core, noEngineReferences, GameWorld.Tick 恒常驱动) ────────────┐
│                                                                                    │
│  Layer 1  世界信息收集 ── 改为「纯数据快照」注入                                    │
│           AnimationWorldSnapshot{ Velocity, MoveInput, Grounded, Tags... }          │
│           ← Unity 侧每帧喂纯数据                                                    │
│                              │                                                     │
│  Layer 2  决策层 ←───────────┘  生成 AnimationRequest{ StateHash, Priority, Source }│
│                              │                                                     │
│  Layer 3  请求层  过滤 · 优先级仲裁 · 双缓冲（原样保留，纯逻辑）                    │
│                              │                                                     │
│  Layer 4  行为层  状态机转换（L2 HFSM） + 混合权重评估（主线程，不 Job 化）          │
│                              │                                                     │
│  Layer 5  运动层  仅保留「运动意图」：算 RootDelta / FacingDelta → 交移动系统(C16)  │
│                   物理计算 / 碰撞 / 地面吸附 → 移交 C16 Physics（本就不属动画）      │
│                              │                                                     │
│                      输出两个契约 ↓  ↓                                              │
└────────────────────────────────────────────────────────────────────────────────┘
                    AnimationStateSnapshot              MotionIntent
                    (姿态意图：状态/时间/权重/事件)       (位移意图 → 移动系统)
                              │ 单向
                              ▼
┌──────────── 表现层 (Unity, 受可见性 / LOD 控制) ──────────────────────────────────┐
│  P1  快照消费 + PlayableGraph 构建/复用（Snapshot.Version 变才重建）               │
│  P2  姿态混合：AnimationMixerPlayable + BlendSpace + AvatarMask（Burst Job 化）     │
│      (AnimationLayerMixerPlayable)                                                 │
│  P2.5 Additive 动画层（详见 12）                                                   │
│  P2.6 Inertialization 惯性化过渡（详见 07）                                        │
│  P3  IK Rig 求解层：AnimationScriptPlayable + IAnimationJob(Burst)（单端口，遵 UUM-34442）│
│  P4  骨骼输出 → AnimationPlayableOutput                                            │
│  P6  PSD 形变：Pose → RBF → 校正权重（读 AnimationStream 姿态）                      │
│  P7  Skinning：LBS / DQ + 校正形变应用（BlendShape / Compute / DOTS 三路径）         │
│  P8  2D 骨骼动画子系统（Spine 类，与 3D 路径并列）：Skeleton2D 求值 + 动态 Mesh      │
│  P5  LOD 控制器 + 可见性开关  ← 新中枢                                             │
└────────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 数据流

```
AnimationWorldSnapshot → DecisionLayer(Layer2) → AnimationRequest
  → RequestLayer(Layer3: filter + prioritize + 双缓冲)
  → BehaviorLayer(Layer4: 状态机转换 + 权重评估)
  → MotionLayer(Layer5: 运动意图)
      ├── AnimationStateSnapshot ──▶ 表现层 P1→P4 ──▶ PlayableGraph ──▶ 骨骼
      └── MotionIntent ──▶ 移动系统(C16)
```
